# 06 — Create booking with full rule enforcement

**What to build:** พนักงานเลือก Room จากผลการค้นหา เลือกตนเองเป็นเจ้าของ กรอกรายละเอียด แล้วยืนยันการจอง โดยระบบบังคับกฎทุกข้อ (ความครบถ้วน, ช่วงเวลาถูกต้อง, ไม่จองย้อนหลัง, Business Hours, Capacity, Conflict) อย่างสม่ำเสมอ และแจ้งเหตุผลเป็นภาษาไทยเมื่อถูกปฏิเสธ — นี่คือคุณค่าหลักของทั้งระบบ

**Blocked by:** 05 — Search available rooms, 03 — Employee management

**Status:** ready-for-agent

- [ ] หน้ายืนยันการจองแสดงห้อง วันที่ และช่วงเวลาที่พามาจากหน้าค้นหา
- [ ] ผู้ใช้เลือกเจ้าของการจองผ่านช่องพิมพ์ค้นหา Employee — ปฏิเสธการจองถ้าไม่ได้เลือกเจ้าของ (FR-EMP-03)
- [ ] ผู้ใช้กรอกหัวข้อการประชุมและจำนวนผู้เข้าร่วม — ปฏิเสธการจองถ้าไม่ได้กรอกหัวข้อ (FR-BKG-11)
- [ ] ปฏิเสธการจองถ้าเวลาสิ้นสุดไม่มากกว่าเวลาเริ่ม (FR-BKG-08)
- [ ] ปฏิเสธการจองถ้าเวลาเริ่มอยู่ในอดีต (FR-BKG-09)
- [ ] ปฏิเสธการจองถ้าช่วงเวลาอยู่นอก Business Hours (FR-BKG-05)
- [ ] ปฏิเสธการจองถ้าจำนวนผู้เข้าร่วมเกิน Capacity ของ Room (FR-BKG-06)
- [ ] ปฏิเสธการจองถ้าช่วงเวลาซ้อนทับกับ Booking สถานะยืนยันแล้วของ Room เดียวกัน (FR-BKG-07)
- [ ] เมื่อไม่ผ่านหลายกฎพร้อมกัน คำตอบแสดงทุกกฎที่ไม่ผ่านเป็นภาษาไทย ไม่ใช่แค่ข้อแรกที่เจอ (FR-BKG-10)
- [ ] การจองที่สำเร็จบันทึกด้วยสถานะยืนยันแล้ว และหน้าจอแสดงรายละเอียดครบทันทีหลังยืนยัน
- [ ] การตรวจ Conflict บังคับที่ระดับฐานข้อมูล/ธุรกรรม: ยิงคำขอสร้าง Booking สองคำขอพร้อมกันสำหรับ Room เดียวกันและช่วงเวลาซ้อนทับ ต้องมีเพียงคำขอเดียวสำเร็จเสมอ ไม่ใช่สำเร็จทั้งคู่
- [ ] การสร้างที่สำเร็จบันทึกร่องรอย (audit) หนึ่งรายการ ระบุประเภทการกระทำ Booking ที่เกี่ยวข้อง รหัส Employee ที่ผู้ใช้เลือก และเวลาที่เกิดขึ้น

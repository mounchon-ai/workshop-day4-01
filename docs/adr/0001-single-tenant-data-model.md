# ใช้ data model แบบ single-tenant (องค์กรเดียว)

ระบบนี้ออกแบบให้รองรับองค์กรเดียวเท่านั้น ไม่มีแนวคิด Organization/Tenant แยกในโมเดลข้อมูล Room และ Employee ทั้งหมดถือว่าเป็นขององค์กรเดียวกันโดยปริยาย

พิจารณาทางเลือก multi-tenant (รองรับหลายองค์กรพร้อมกัน) แล้วปฏิเสธ เพราะโจทย์ปัจจุบันเป็นเครื่องมือภายในองค์กรเดียว การทำ multi-tenant เพิ่ม complexity ให้ data model และ authorization โดยไม่มีความจำเป็นในตอนนี้

หากในอนาคตต้องรองรับหลายองค์กร จะต้องเพิ่ม tenant identifier ให้ทุก entity และ retrofit การกรองข้อมูลตาม tenant ทั่วทั้งระบบ ซึ่งเป็นการเปลี่ยนแปลงที่มีต้นทุนสูง

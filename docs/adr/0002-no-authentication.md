# ไม่มีระบบ authentication ระบุตัวตนผู้จองผ่าน Employee picklist แทน

ระบบไม่มีระบบ login/password ผู้ใช้ระบุตัวตนของตนเองตอนสร้าง Booking โดยเลือกชื่อจากรายชื่อ Employee ที่กำหนดไว้ล่วงหน้า (mock data) ไม่มีการยืนยันตัวตนจริง สิทธิ์ในการยกเลิก/แก้ไข Booking (ดู [[Ownership]] ใน CONTEXT.md) จึงอ้างอิงจากชื่อที่ผู้ใช้เลือกเอง ไม่ใช่ session ที่ผ่านการยืนยัน

เลือกทางนี้เพราะโปรเจกต์นี้เป็นต้นแบบ/เดโมที่มี role ผู้ใช้แบบเดียว เน้นความเร็วในการสร้างฟีเจอร์หลัก (การจองห้อง) มากกว่าความปลอดภัย

ผลที่ตามมา: ระบบนี้ไม่เหมาะสำหรับใช้งานจริงในสภาพแวดล้อมที่ต้องการความปลอดภัย เพราะใครก็ตามที่เข้าถึงระบบสามารถปลอมเป็น Employee คนอื่นเพื่อยกเลิก/แก้ไข Booking ของคนอื่นได้ หากต้องนำไปใช้งานจริงต้องเพิ่มระบบ authentication (เช่น Auth.js) ก่อน ซึ่งจะกระทบ flow การสร้าง Booking ทั้งหมด

# บทที่ 1 บทนำ

## 1.1 วัตถุประสงค์ของเอกสาร

เอกสารฉบับนี้กำหนดความต้องการของ **ระบบจองห้องประชุม (Meeting Room Booking)** สำหรับใช้งานภายในองค์กรเดียว เพื่อให้ทุกฝ่ายที่เกี่ยวข้องเข้าใจตรงกันว่าระบบต้องทำอะไรได้บ้าง ต้องทำได้ดีเพียงใด และจะตรวจรับอย่างไร

ผู้อ่านเป้าหมายและวิธีใช้เอกสาร

| ผู้อ่าน | ใช้เอกสารนี้เพื่อ | บทที่เกี่ยวข้องที่สุด |
|---|---|---|
| ผู้ว่าจ้าง / เจ้าของงาน | ยืนยันว่าขอบเขตงานตรงกับความต้องการ | บทที่ 1, 2, 7 |
| ทีมพัฒนา | ใช้เป็นฐานในการออกแบบและพัฒนา | บทที่ 3, 5, 6 |
| ผู้ทดสอบ / ผู้ตรวจรับ | สร้างกรณีทดสอบและเกณฑ์ตรวจรับ | บทที่ 3, 4, 7 |
| เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล | ตรวจความสอดคล้องกับ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล | บทที่ 4, 5 |

เอกสารนี้กำหนด **"อะไร"** ไม่ใช่ **"อย่างไร"** รายละเอียดการออกแบบภายในอยู่นอกขอบเขตของเอกสารฉบับนี้ ยกเว้นส่วนที่ถูกตรึงไว้แล้วด้วยข้อตัดสินใจเชิงสถาปัตยกรรม (ADR) ซึ่งระบุไว้เป็นข้อจำกัดในหัวข้อ 2.4

## 1.2 ขอบเขตของระบบ

ระบบจองห้องประชุมเป็นเครื่องมือภายในองค์กรที่ให้พนักงานค้นหาห้องประชุมที่ว่าง เลือกช่วงเวลา และยืนยันการจองได้ด้วยตนเองผ่านเว็บเบราว์เซอร์ โดยไม่ต้องผ่านเจ้าหน้าที่ธุรการและไม่ต้องเข้าสู่ระบบ ระบบทำหน้าที่บังคับกฎการจองสามข้อโดยอัตโนมัติ ได้แก่ ช่วงเวลาทำการ (Business Hours) ความจุห้อง (Capacity) และการซ้อนทับของช่วงเวลา (Conflict)

### 1.2.1 อยู่ในขอบเขต (In Scope)

| ลำดับ | รายการ |
|---|---|
| 1 | ค้นหา Room ที่ว่างตามวันที่ ช่วงเวลา และจำนวนผู้เข้าร่วม |
| 2 | ดูปฏิทินการใช้งาน Room รายวัน |
| 3 | สร้าง Booking โดยระบุตัวตนผ่านการเลือกชื่อจากรายการ Employee |
| 4 | บังคับกฎ Business Hours, Capacity และ Conflict โดยอัตโนมัติ ณ เวลาที่สร้างและแก้ไข Booking |
| 5 | แก้ไขและยกเลิก Booking โดยผู้ที่มี Ownership |
| 6 | ดูรายการ Booking ของตนเอง |
| 7 | จัดการข้อมูล Room (เพิ่ม แก้ไข ปิดการใช้งาน) |
| 8 | จัดการรายการ Employee ที่ใช้เป็นตัวเลือกเจ้าของ Booking |

### 1.2.2 อยู่นอกขอบเขต (Out of Scope)

| ลำดับ | รายการที่ไม่ทำ | เหตุผล / ที่มา |
|---|---|---|
| 1 | รองรับหลายองค์กรพร้อมกัน (multi-tenant) | ระบบออกแบบสำหรับองค์กรเดียว (ที่มา: ADR-0001) |
| 2 | ระบบเข้าสู่ระบบด้วยรหัสผ่าน และการยืนยันตัวตนจริง | ระบุตัวตนด้วยการเลือกชื่อจากรายการแทน (ที่มา: ADR-0002) |
| 3 | การกำหนดสิทธิ์ตามบทบาท (role-based access control) | ผลสืบเนื่องจากการไม่มีการยืนยันตัวตน (ที่มา: ADR-0002) |
| 4 | Booking แบบเกิดซ้ำตามรอบ (recurring) | นิยาม Booking ใน `CONTEXT.md` กำหนดว่าเป็นการจองครั้งเดียว |
| 5 | ขั้นตอนขออนุมัติการจองจากผู้บังคับบัญชา | ไม่ปรากฏในภาษากลางของโดเมน |
| 6 | การจองอุปกรณ์หรือบริการเสริม (โปรเจกเตอร์ อาหารว่าง) | ไม่ปรากฏในภาษากลางของโดเมน |
| 7 | การเชื่อมต่อระบบข้อมูลบุคลากรแบบอัตโนมัติ | รายการ Employee เป็นข้อมูลที่เตรียมไว้ล่วงหน้า (ที่มา: ADR-0002) |
| 8 | การติดตั้งแบบหลาย instance และการเขียนพร้อมกันปริมาณสูง | ข้อจำกัดของฐานข้อมูลที่เลือกใช้ (ที่มา: ADR-0003) |
| 9 | การแจ้งเตือนผ่านอีเมลหรือปฏิทินภายนอก | ไม่ปรากฏในภาษากลางของโดเมน `[ต้องยืนยัน]` |

## 1.3 นิยามศัพท์และอภิธานศัพท์

ตารางนี้ถอดมาจาก `CONTEXT.md` ทั้งฉบับ และเป็น **สัญญาว่าเอกสารชุดนี้จะใช้คำใด** คอลัมน์ "คำที่ไม่ใช้" คือคำพ้องความหมายที่ห้ามปรากฏในเอกสาร เพื่อไม่ให้ผู้อ่านเข้าใจว่าเป็นคนละสิ่ง

| คำศัพท์ | ความหมาย | คำที่ไม่ใช้ | หมายเหตุ |
|---|---|---|---|
| **Room** | พื้นที่ประชุมทางกายภาพที่จองได้ มีชื่อ ความจุ (Capacity) และตำแหน่งที่ตั้ง (ชั้น/อาคาร) | Meeting space, Venue | ภาษาไทยใช้ "ห้องประชุม" ได้ |
| **Employee** | บุคคลในองค์กรที่ระบุตัวตนได้จากรายการที่กำหนดไว้ล่วงหน้า ใช้เป็นเจ้าของ Booking ไม่มีการยืนยันตัวตนด้วยรหัสผ่าน | User, Account, Member | ภาษาไทยใช้ "พนักงาน" |
| **Booking** | การจอง Room หนึ่งห้องในช่วงเวลาหนึ่งแบบครั้งเดียว มี Employee หนึ่งคนเป็นเจ้าของ พร้อมหัวข้อการประชุมและจำนวนผู้เข้าร่วม | Reservation, Appointment, Event | ภาษาไทยใช้ "การจอง" |
| **Business Hours** | ช่วงเวลาที่อนุญาตให้ Booking เริ่มต้นและสิ้นสุดได้ ค่าเริ่มต้น 08:00–18:00 วันจันทร์ถึงศุกร์ | Operating hours, Working hours | ภาษาไทยใช้ "ช่วงเวลาทำการ" |
| **Conflict** | สถานะที่ Booking สองรายการของ Room เดียวกันมีช่วงเวลาซ้อนทับกัน ระบบต้องปฏิเสธการสร้าง Booking ที่ก่อให้เกิด Conflict โดยอัตโนมัติ | Double-booking, Overlap | ภาษาไทยใช้ "การซ้อนทับของช่วงเวลา" |
| **Capacity** | จำนวนผู้เข้าร่วมประชุมสูงสุดที่ Room รองรับได้ | Seats, Max occupancy | ภาษาไทยใช้ "ความจุ" |
| **Ownership** | ความสัมพันธ์ระหว่าง Booking กับ Employee ผู้สร้าง มีเพียง Employee เจ้าของเท่านั้นที่ยกเลิกหรือแก้ไข Booking นั้นได้ | Organizer, Creator | ภาษาไทยใช้ "ความเป็นเจ้าของ" |

**หมายเหตุการอ่านคำว่า "User"** — คำนี้ห้ามใช้เรียก Employee แต่ยังปรากฏในศัพท์เทคนิคตายตัวที่ไม่ได้หมายถึงบุคคลในโดเมน ได้แก่ *User Interface* (ส่วนติดต่อผู้ใช้, หัวข้อ 6.1) และ *Concurrent User* (จำนวนผู้ใช้พร้อมกัน, หัวข้อ 4.1) เมื่อหมายถึงบุคคลในโดเมนให้ใช้ "Employee" หรือ "พนักงาน" เสมอ

### คำย่อ

| คำย่อ | ความหมายเต็ม |
|---|---|
| ADR | Architecture Decision Record — บันทึกข้อตัดสินใจเชิงสถาปัตยกรรม |
| BPMN | Business Process Model and Notation — สัญกรณ์แบบจำลองกระบวนการทางธุรกิจ |
| DFD | Data Flow Diagram — แผนภาพกระแสข้อมูล |
| ERD | Entity Relationship Diagram — แผนภาพความสัมพันธ์ของข้อมูล |
| FR / NFR | Functional / Non-Functional Requirement — ความต้องการเชิงหน้าที่ / ที่ไม่ใช่เชิงหน้าที่ |
| PDPA | Personal Data Protection Act — พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 |
| RTM | Requirement Traceability Matrix — ตารางสอบทานความต้องการ |
| RTO / RPO | Recovery Time / Point Objective — เป้าหมายเวลาและจุดที่กู้คืนข้อมูลได้ |
| TOR | Terms of Reference — ขอบเขตของงาน |
| UC | Use Case — กรณีการใช้งาน |
